\noindent
\textbf{Abstract}\\
Analyzing street network topology usually requires programming skills. We present StreetNets, a no-code dashboard built with Streamlit and OSMnx that makes OpenStreetMap street networks accessible to non-technical users. Users define an area of interest in five ways, from a place name to an uploaded shapefile, and obtain topological metrics, a functional road hierarchy (Highways, Arterial, Local), interactive maps, and exports in standard GIS formats. When installed locally, StreetNets also computes centrality, street orientation, and disruption and robustness analyses, and compares any network against a database of 18 pre-analyzed cities, bridging complex network methods and practical urban planning workflows.

\section{Introduction}

A network is called \emph{spatial} when its nodes are embedded in a space with a notion of distance; distance then constrains connections, so nodes far apart are less likely to be linked \cite{barthelemy2011spatial, barthelemy2022spatial}. Street networks are a canonical example: intersections and dead-ends are nodes, street segments are edges, and the physical geometry dictates both \cite{boeing2017osmnx}. Modeling a city as a graph $G=(V,E)$ allows its structure to be quantified with network science tools, from simple size measures to centrality and robustness.

Turning raw geographic data into consistent graphs, however, is technically demanding. OSMnx \cite{boeing2017osmnx, boeing2025osmnx} solved much of this problem by integrating OpenStreetMap (OSM) with NetworkX, but it remains a Python library and is out of reach for users who do not program. StreetNets is a no-code dashboard, powered by OSMnx, that lets researchers, urban planners, and the general public retrieve, visualize, analyze, and export street networks for any area of the world through a graphical interface. An early version of the tool was presented at GEOINFO 2024 \cite{streetnets_geoinfo2024}; this article describes the substantially extended current version, which adds new input methods, a database of pre-analyzed cities, advanced network analyses, and a locally installable package.

\section{Software description}

StreetNets is implemented in Python with the Streamlit framework, which handles the interface, session state, and data flow (Figure~\ref{fig:flow}). It can be used through a hosted web deployment or installed as a Python package that runs entirely on the user's computer. The application is organized into five pages: Home, Retrieve City Data, City Database, Deep Analysis, and Glossary.

\begin{itemize}
    \item \textbf{Input.} The area of interest is defined in one of five ways: a point with a buffer distance, a geocoding query (e.g., a neighborhood or city name), a bounding box, a polygon drawn on an interactive map, or an uploaded shapefile (.zip). The user also selects the network type (e.g., drivable, walkable, all streets).

    \item \textbf{Retrieval.} OSMnx queries OSM and builds a directed graph $G(V,E)$ with the retrieval function suited to the input (e.g., \textit{graph\_from\_point}, \textit{graph\_from\_polygon}), including OSMnx's topological simplification.

    \item \textbf{Analysis.} The graph is converted into GeoDataFrames and summarized by the number of nodes $N=|V|$ and edges $M=|E|$, the total street length $L_{total}=\sum_e l_e$, and the average segment length $\bar{l}=L_{total}/M$, a proxy for urban granularity. Edges are also classified into a functional hierarchy using OSM \texttt{highway} tags: \textbf{Group A (Highways)} contains motorways and trunk roads for high-speed, long-distance traffic; \textbf{Group B (Arterial)} contains primary, secondary, and tertiary roads forming the city's distributor skeleton; and \textbf{Group C (Local)} contains residential and other minor streets providing local access (Figure~\ref{fig:stats}).

    \item \textbf{Visualization and export.} Results are shown as metric cards, Plotly charts of the road-type and group distributions, and Folium maps of the network colored by group. The network can be downloaded as ESRI Shapefile, GeoJSON, GeoParquet, Feather, GeoPackage, SQLite, or CSV, bundled into a single ZIP archive.

    \item \textbf{City Database.} Pre-computed statistics and hierarchy maps for 18 cities on four continents (e.g., São Paulo, Rio de Janeiro, Manhattan, London, Barcelona, Buenos Aires), allowing cross-city comparison without any computation. When the package is installed, the dataset is downloaded automatically on first use.

    \item \textbf{Deep Analysis.} Research-grade metrics computed with python-igraph \cite{csardi2006igraph} on either a retrieved network or a database city: length-weighted edge betweenness and closeness centrality, with maps and distributions (Figure~\ref{fig:deep}); street orientation entropy and orientation compass \cite{boeing2019orientation}; disruption simulation, where the user draws a polygon (e.g., a flooded area or a road closure) and the tool reports the removed street length, the new number of connected components, and the share of nodes cut off from the main network \cite{boeing_resilient_2024}; robustness curves comparing targeted (highest-betweenness first) and random street removal; and percentile comparison of the network's statistics against the 18-city database. Because these computations are too heavy for a shared server, this page is enabled only in local installations.

    \item \textbf{Glossary.} Plain-language explanations of every technical term used in the interface, aimed at non-specialist users.
\end{itemize}

\section{Impact overview}

OSMnx is an established tool in urban analytics, widely adopted for producing topologically correct graphs from raw OSM data \cite{boeing2017osmnx}. StreetNets extends this capability to users who do not program. Its first version was peer-reviewed and presented to the Brazilian geoinformatics community at GEOINFO 2024 \cite{streetnets_geoinfo2024}, and the tool has since grown from a data retrieval interface into a full analysis environment. Its impact can be summarized as follows:

\begin{itemize}
    \item \textbf{New users and research questions.} Urban planners, geographers, civil defense staff, and students can obtain analysis-ready street graphs and network metrics without writing code, and can bring them into existing GIS workflows (QGIS, ArcGIS) through standard formats. This makes network-based questions, such as which streets concentrate shortest paths or which areas become isolated when a region floods, accessible to practitioners outside network science.
    \item \textbf{Faster research workflows.} For researchers, StreetNets reduces area-of-interest definition, retrieval, cleaning, and export to a few clicks, and provides consistent graphs and metrics across cities. The tool was used to acquire the street networks studied in \cite{soares2024}, where navigational bottlenecks in diffusive dynamics were identified on urban networks.
    \item \textbf{Comparative context.} The 18-city database and the percentile comparison let users place any area within a reference distribution of real cities, rather than interpreting its metrics in isolation.
    \item \textbf{Disaster risk and resilience.} The disruption and robustness tools allow quick assessment of how flooding, landslides, or road works affect network connectivity, which is relevant to monitoring and early-warning institutions such as Cemaden.
    \item \textbf{Teaching.} The visual interface and glossary make StreetNets suitable for teaching complex networks and urban morphology.
\end{itemize}

\section{Limitations and future improvements}

Advanced metrics such as betweenness centrality and robustness curves scale poorly with network size, and real-time computation for large networks with tens of thousands of intersections is impractical on a shared web server. StreetNets addresses this by offering a local installation (\texttt{pip install .}, launched with the \texttt{streetnets} command), in which the Deep Analysis page runs on the user's own hardware; the hosted deployment provides retrieval, statistics, maps, export, and the City Database. Even locally, very large areas remain computationally expensive, and interactive maps are sampled above a feature limit to keep the interface responsive. Results also inherit the completeness and tagging quality of OSM, which varies between regions.

Future work includes approximate centrality algorithms for very large networks, additional topological and accessibility metrics, expansion of the city database, and support for multimodal networks (e.g., combining street and public transport layers).
